Data Retention and Deletion

Version 1.0 · Effective October 29, 2026 · Next review October 2027

Tallyho keeps consumer financial data only while it is connected and in use, and deletes it, at Plaid and locally, when a connection is removed. This policy covers every copy of data Tallyho receives from Plaid or imports from files: the live data, backups, logs, reports and exports.

1. Data covered

All consumer data in Tallyho belongs to the operator. Tallyho holds no data about anyone else.

Tallyho does not store bank usernames or passwords. Those are entered only in Plaid Link and never reach Tallyho.

2. Where data is stored

All data stays on the operator's own computer, which uses full-disk encryption. Nothing is synced to a cloud service. The data and backups are readable only by the operator's account, connection credentials and backups are encrypted a second time, and logs hold job status only, never credentials or transactions.

4. Deletion

Disconnecting one institution

  1. Tallyho asks Plaid to remove the connection, which revokes its credentials. Plaid stops pulling data for it.
  2. Tallyho deletes the connection and its credentials.
  3. That deletion removes every account, transaction, balance, card or loan term and holding under it.
  4. Copies in backups age out within about two weeks.

Deleting all data

  1. Disconnect every institution as above, so each connection is revoked at Plaid.
  2. Stop Tallyho and its scheduled jobs.
  3. Delete the data, backups, logs, reports and any exports.
  4. Delete the encryption key, which makes any remaining backup copy unreadable.
  5. Delete the Plaid API credentials and rotate them in the Plaid Dashboard.

A request to delete data, from the operator or from Plaid, is completed within 30 days.

5. Backups, reports and logs

  • Backups are taken nightly, encrypted and readable only by the operator. They rotate automatically, so deleted data is gone from them within about two weeks.
  • Backups never leave the computer, and are never copied to cloud storage. A restore brings back only what that backup held, and any institution disconnected since then is disconnected again straight after.
  • Reports are reviewed and pruned each quarter. Anything older than 24 months is deleted.
  • Logs hold job status, not financial data, and are cleared each quarter, keeping the last 90 days.

6. Device disposal

Before the computer is sold, given away, repaired by a third party or retired, all Tallyho data is deleted as above and the computer is fully erased, which destroys its disk-encryption key.

If the computer is lost or stolen, the operator rotates the Plaid API credentials within 24 hours. Connection credentials are useless without them, so no one holding the device can pull new data, and the data already on it stays protected by disk encryption.

7. Ownership and review

  • The operator owns this policy and is responsible for following it.
  • It is reviewed once a year, and whenever Tallyho starts storing a new kind of data or in a new place.
  • Plaid's own retention of the data it collects is governed by the Plaid End User Privacy Policy, not by this policy.
  • Any exception is written down with its reason and an end date.
